


# Диаграмма классов: Интернет-магазин
## Диаграмма (Mermaid)
## Список классов с пояснением их роли
| Класс | Роль | Пояснение |
|-------|------|-----------|
| **Пользователь** | Базовый класс | Содержит общие данные (id, имя, email) и методы для всех пользователей системы. Абстрактный по смыслу. |
| **Покупатель** | Основной пользователь | Наследует Пользователя. Оформляет заказы, управляет корзиной, накапливает бонусные баллы. |
| **Администратор** | Привилегированный пользователь | Наследует Пользователя. Управляет каталогом товаров (добавление, удаление). |
| **Товар** | Товарная позиция | Описывает товар в каталоге: id, название, цена, остаток на складе. |
| **Заказ** | Оформленный заказ | Фиксирует заказ с датой, суммой и статусом (оплачен, доставлен и т.д.). |
| **Корзина** | Временное хранилище | Содержит товары, выбранные покупателем до оформления заказа. |
| **Платеж** | Транзакция | Обрабатывает оплату заказа (проведение платежа, возврат). |
## Описание ключевых отношений
| Отношение | Тип | Участники | Пояснение |
|-----------|-----|-----------|-----------|
| **Наследование** | Generalization | Пользователь ← Покупатель, Пользователь ← Администратор | Покупатель и Администратор — частные случаи Пользователя. Наследуют id, имя, email и методы. |
| **Композиция** | Composition | Покупатель → Корзина | У каждого покупателя ровно одна корзина. Если удалить покупателя — корзина удаляется автоматически. |
| **Агрегация** | Aggregation | Заказ → Товар | Заказ содержит товары, но товары существуют независимо (их можно удалить из каталога, но информация о них в заказе сохранится). |
| **Ассоциация** | Association | Покупатель (1) ↔ Заказ (0..*) | Один покупатель может иметь много заказов. Каждый заказ принадлежит одному покупателю. |
| **Зависимость** | Dependency | Заказ → Платеж | Заказ временно использует Платеж для оплаты. Платеж не является постоянной частью заказа. |
## Объяснение выбранных типов связей
**1. Наследование** 
Покупатель и Администратор — разные роли, но оба являются пользователями. Наследование позволяет не дублировать общие атрибуты (имя, email) и методы (войти).
**2. Композиция (Покупатель → Корзина)** 
Корзина не может существовать без покупателя. При удалении аккаунта корзина теряет смысл и удаляется. Это строгая связь (чёрный ромб).
**3. Агрегация (Заказ → Товар)** 
Товары живут своей жизнью в каталоге. Один товар может быть в разных заказах. Если заказ удалить — товар остаётся. Это мягкая связь (пустой ромб).
**4. Ассоциация (Покупатель — Заказ)** 
Прямая связь между покупателем и заказами. Множественность: 1 покупатель → много заказов, 1 заказ → 1 покупатель.
**5. Зависимость (Заказ → Платеж)** 
Платеж создаётся в момент оплаты и не хранится внутри заказа постоянно. Это слабая временная связь.
## Нотация видимости (обозначения)
| Символ | Значение | Пример |
|--------|----------|--------|
| `+` | открытый (public) | `+ оформитьЗаказ()` |
| `-` | закрытый (private) | `- бонусныеБаллы: int` |
| `#` | защищённый (protected) | `# уровеньДоступа: int` |
